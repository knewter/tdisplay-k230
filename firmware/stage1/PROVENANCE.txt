K230 stage 1 -- provenance
==========================
Rewritten 2026-09-22 (every-blob-is-built-from-source-or-named, task 5.3).
The text this replaces described five vendor-compiled binaries that lived
in this directory; it is in git history at 6c5d50c if the Docker-era
details are ever needed.

Stage 1 is built from source by the flake. This directory holds one text
file and no binary:

  tdisplay.env    the U-Boot environment, as text. The SDK's default.env
                  with three changes, each observed on hardware
                  (docs/evidence/hardware-boot.txt): the device tree and
                  OpenSBI load addresses moved above a 57 MiB kernel, and
                  a bootargs.txt import so the kernel command line can
                  name the NixOS closure without the environment changing
                  on every rebuild.

What produces the five files the card carries
---------------------------------------------
  nix/k230-sdk-src.nix    kendryte/k230_linux_sdk @ 1104236, fetched
                          sparsely: the two overlays and the env directory,
                          287 files, all text
  nix/uboot-k230.nix      U-Boot 2022.10 (upstream tarball, sha256
                          50b4482a...) with Canaan's overlay copied over it,
                          k230_canmv_v3_defconfig, nixpkgs riscv64 cross GCC
                          -> u-boot.bin, spl/u-boot-spl.bin
  nix/opensbi-k230.nix    OpenSBI v1.4 with Canaan's nine-file overlay,
                          generic platform, FW_TEXT_START=0, GCC 13,
                          FW_JUMP_FDT_ADDR left undefined
                          -> fw_jump.bin
  nix/stage1.nix          the packaging, step for step from the SDK's
                          post-image.sh with nixpkgs gzip in place of the
                          vendor's renamed one -> fn_u-boot-spl.bin,
                          fn_ug_u-boot.bin, env.env, fw_jump.bin,
                          fw_jump_add_uboot_head.bin

  nix build .#stage1      builds all five; SHA256SUMS is in the output

Where they go on the card (nix/sd-image.nix, from the SDK's genimage.cfg;
raw, outside the partition table):

  fn_u-boot-spl.bin   1 MiB (0x100000) AND again at 1.5 MiB (0x180000)
  fn_ug_u-boot.bin    2 MiB (0x200000)
  env.env             3 MiB (0x300000) AND again at 3.5 MiB (0x320000)
  fw_jump_add_uboot_head.bin   in the boot ext4, at its root; blinux
                               ext4loads it by name

What stays opaque
-----------------
The Synopsys DDR PHY training firmware: 32 768 bytes of instruction memory
(sha256 517aa534...) and 1 660 bytes of data memory (1c0819e8...), arriving
as C in the overlay and compiled into the SPL. Building from source moved
it (0x23f80 in u-boot-spl.bin, 0x24184 in fn_u-boot-spl.bin) and did not
remove it. docs/blob-inventory.md A5-A6.

The vendor-compiled fallback
----------------------------
tools/gen-stage1.sh still builds the same five files the old way -- the
SDK in Docker with the 1.9 GB Xuantie toolchain -- into this directory,
gitignored, and `K230_STAGE1=vendor ./tools/flash-latest.sh` (or
`K230_STAGE1_DIR=$PWD/firmware/stage1 nix build --impure .#sdImage`)
builds an image from them. That is a bisect tool: the bytes the board
booted before stage 1 was built here, for when a from-source change
fails and the question is whether the change or the build is at fault.
It is not the default anywhere, and nothing reads this directory unless
asked to by name.
