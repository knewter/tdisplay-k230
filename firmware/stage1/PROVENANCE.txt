K230 stage-1 firmware — provenance (tasks 1.1, 1.2)
====================================================
Built 2026-09-20 on solomon. NOT written by this project: these are the
vendored boot chain, and openspec/specs/image/boot-chain requires that we
never build them from source as part of our own image.

Regenerate with tools/gen-stage1.sh, which reproduces the SDK's
gen_uboot_bin() from buildroot-overlay/board/canaan/k230-soc/post-image.sh
rather than approximating it. Note it uses the SDK's private
tools/k230_priv_gzip -n8, not stock gzip.

Files and where they go on the card
------------------------------------
Offsets from the SDK's genimage_cfg/genimage.cfg. All raw, outside the MBR
partition table.

  fn_u-boot-spl.bin   1 MiB (0x100000) AND again at 1.5 MiB (0x180000)
  fn_ug_u-boot.bin    2 MiB (0x200000)
  env.env             3 MiB (0x300000) AND again at 3.5 MiB (0x320000)

Each carries a Canaan firmware header: magic "K230", no encryption,
SHA-256 integrity, applied by the U-Boot tree's
tools/firmware_gen_no_securiy.py.

Why these are committed rather than fetched
--------------------------------------------
the-board-boots-what-we-built's design said to pin stage 1 as a
fixed-output derivation and rejected committing it as "several megabytes of
opaque vendor output". Measured, it is 570 KB, and a fixed-output derivation
needs a URL to fetch from -- but these were BUILT here, not downloaded, so
there is no URL. Committing them makes the repository self-contained: an
image can be built without Docker, without the 284 MB SDK checkout and
without the 1.9 GB toolchain. The provenance above and tools/gen-stage1.sh
are what make that honest rather than mysterious.

OpenSBI (added 2026-09-20)
--------------------------
  fw_jump.bin                  built from source, OpenSBI 1.4
  fw_jump_add_uboot_head.bin   the same with a U-Boot image header

Built in the same container from the SDK's own OpenSBI package:
  version   1.4  (BR2_TARGET_OPENSBI_CUSTOM_VERSION_VALUE="1.4")
  platform  generic, with Canaan's T-Head overlay at
            buildroot-overlay/boot/opensbi/opensbi-1.4-overlay/platform/generic/thead
  extra     FW_TEXT_START=0

The header is applied exactly as post-image.sh does:
  mkimage -A riscv -O linux -T kernel -C none -a 0 -e 0 -n linux \
          -d fw_jump.bin fw_jump_add_uboot_head.bin

This one goes INSIDE the boot ext4 at the root, not into the raw region --
vendored U-Boot ext4loads /fw_jump_add_uboot_head.bin to 0x3000000 and
bootm's it. See docs/evidence/uboot-env.txt.

Note for the blob inventory: unlike the DDR training firmware, this is
compiled from published source (riscv/opensbi 1.4 plus Canaan's overlay,
both readable). It is committed for the same build-convenience reason as
U-Boot, not because source is unavailable, and building it inside the flake
would remove it from the tree entirely.
