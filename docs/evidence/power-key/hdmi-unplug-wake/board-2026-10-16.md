# HDMI unplug lights the panel: board run 2026-10-16

Change: `the-display-lights-when-hdmi-is-unplugged`. Evidence class: board
journal and Sway IPC state. The operator handled the cable and pressed the
power key, and reported "works" (the panel lit after the unplug). There was
no camera recording.

## Installed

The system was deployed live from commit `91a60bfb` (first implementation,
which woke the display on the relay's Trackpad → DirectTouch edge):
`/nix/store/b6wn851s2005i1gm6r6pnxk72waajzl3-nixos-system-nixos-26.11.20260919.20b1ddd`.

## Journal (filtered, same boot)

```
13:36:10 kernel: canaan-mipi-dsi 90850000.dsi: HDMI HPD: connected
13:36:12 k230-touch-trackpad: mode -> Trackpad (panel connected: false)
13:36:29 kernel: k230-pmu-pwrkey: INT0 press / INT0 release
13:36:29 sway: Handling command 'output * power off'
13:36:30 k230-touch-trackpad: mode -> DirectTouch (panel connected: false)
13:36:30 sway: Handling command 'output * power on'
13:36:31 kernel: canaan-mipi-dsi 90850000.dsi: HDMI HPD: disconnected
13:36:31 sway: Handling command 'output * power on'
13:36:32 k230-touch-trackpad: mapped direct touch to DSI-1 and powered the display on
```

Afterwards, `swaymsg -t get_outputs` reported `DSI-1` with `"power": true`.

## What it shows

- The unplug lit the panel with direct touch, as the operator reported.
- It also exposed a flaw in that first implementation. The power-key blank at
  13:36:29 disabled HDMI scanout with the cable still in. The relay then left
  trackpad mode at 13:36:30 and sent `power on`, one second before HPD
  reported the unplug. With the cable left in, that would have turned the
  monitor straight back on after every power-off.
- Commit `28302fb3` makes the wake depend on the HDMI connector `status`
  changing from `connected` to not connected. Its board check is task 1.4.
