U-Boot on the board and USB: the baseline before `ums` (tasks 1.1-1.4)
======================================================================
2026-09-22 07:18-07:22, solomon, the board held under /tmp/k230-board.lock for the whole
session and released once Linux was back at its login prompt. The stage 1 on the card is
this project's own build (docs/evidence/stage1-from-source.txt: SPL fe3d537f, U-Boot
805bd543, OpenSBI 9627edbe) -- so what U-Boot reports below is what nix/uboot-k230.nix
produces from k230_canmv_v3_defconfig with no USB-gadget configuration.

How the prompt was reached. `reboot` was sent to Linux over the console, then
tools/capture-boot.py --hammer 20 --kick --expect 'K230# ' with one --send per command.
A warm reboot did NOT drop the CH342 console port: the capture shows a single
`--- port opened ---` at 0.007 s and no `--- port lost ---` (contrast the cold boot in
docs/evidence/boot-from-source-cold.txt, where the bridge loses power with the board and
the SPL/U-Boot banners fall in the re-enumeration gap). With the port alive through the
reset, the hammered keys hit the 1 s `bootdelay` and U-Boot stopped at its prompt. The
board was returned to Linux with `boot` at the end of the same session; line 875 of the
transcript is `nixos login: root (automatic login)`.

Every command's output appears twice in the transcript: once as the board echoes it
and once from the tool's own read of the same bytes. That is an artefact of the capture,
not the board repeating itself.

What each task asked, and what the board said
---------------------------------------------
1.1  `help ums` / `help k230_dfu`
       Unknown command 'ums' - try 'help' without arguments for list of all known commands
       k230_dfu - k230 burntool enter dfu
     `ums` absent, `k230_dfu` present: the tree nix/uboot-k230.nix compiles is what is on
     the card, and it has no gadget. `version` for the record:
       U-Boot 2022.10 (Oct 03 2022 - 19:25:32 +0000)
       riscv64-unknown-linux-gnu-gcc (GCC) 15.3.0
       GNU ld (GNU Binutils) 2.46
     (the date is SOURCE_DATE_EPOCH's, the compiler is nixpkgs', not Xuantie's).

1.2  `dm tree` -- the before half of design D3
       usb           0  [   ]   dwc2_usb              |   |-- usb-otg@91540000
     One snps,dwc2 node bound, usb-otg@91540000 (usbotg1, the onboard RTL8152), to the
     HOST driver dwc2_usb. usb-otg@91500000 (usbotg0, the J3 data USB-C) is absent from
     the tree entirely: k230.dtsi leaves it `status = "disabled"` without CONFIG_CMD_DFU.
     No gadget uclass exists.

1.3  `usb start` / `usb tree` -- what variant A1 gives up
       Bus usb-otg@91540000: dwc2_usb usb-otg@91540000: Core Release: 4.30a
       scanning bus usb-otg@91540000 for devices... 2 USB Device(s) found
       USB device tree:
         1  Hub (480 Mb/s, 0mA)   U-Boot Root Hub
         |+-2  Vendor specific (480 Mb/s, 100mA)   Realtek USB 10/100 LAN 000000000000
     Yes: today's U-Boot enumerates the onboard RTL8152 over usbotg1 (a MAC of all zeros;
     no driver bound it as an ethernet device -- `Net: No ethernet found.` on the banner).
     Turning CONFIG_USB_DWC2 off removes this from U-Boot; Linux is unaffected.

1.4  `mmc list` / `mmc dev 1` / `mmc info` -- the argument `ums` will take
       mmc0@91580000: 0
       mmc1@91581000: 1 (SD)
       Device: mmc1@91581000   Name: SD128   SD version 3.0   High Capacity: Yes
       Capacity: 119.1 GiB   Bus Width: 4-bit   Mode: SD High Speed (50MHz)
     The card is mmc 1, 119.1 GiB. `ums 0 mmc 1` is the command, once `ums` exists.

Also recorded: `printenv bootcmd bootdelay` -> bootcmd=run blinux; bootdelay=1.
