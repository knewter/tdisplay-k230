--- budgets -------------------------------------------------------------

  MAX_BUILD_SECONDS = 120.0     measured  6.5 s    ~18x headroom
  MAX_OUTPUT_BYTES  = 8 MiB     measured 47 KiB   ~176x headroom

Set high on purpose. A cold GitHub runner pays Node start-up and a Vite
build that a warm 5950X does not, and the capability taxonomy in
.skills/k230-spec-change/SKILL.md allows fifteen capabilities where this
tree has one. A breach should mean something changed -- an evidence file
the size of a video, or a build that started doing real work -- not that
the numbers were always tight. A budget raised reflexively means nothing.

A forced breach names both numbers:

$ ./scripts/build_site.py --max-bytes 1
error: output is 44891 bytes against a budget of 1 bytes

--- deployment ----------------------------------------------------------

.github/workflows/spec-site.yml runs the same command on every push to
main and publishes site/dist to GitHub Pages at
https://knewter.github.io/tdisplay-k230/.

Run 35536825120 installed the dependencies, ran the data-pass tests and
built the site successfully on ubuntu-latest -- and then failed at
actions/configure-pages. GitHub Pages has never been enabled on the
repository, and the workflow's attempt to enable it (enablement: true)
was refused: the Actions token is not permitted to create a Pages site.
That is a repository setting, not something CI can do.

Until a deployment completes, the requirement 'The published site is
current without anyone maintaining it' stays UNVERIFIED. That is the
correct output, and it is what the site itself says on its own page.
