Against the estimate of 89 derivations / 875 MiB in
docs/display-environment-options.md these look far worse, and the
difference has three parts, each checked rather than guessed:

1. The count includes non-compile derivations. The 139 for the compositor
   include ~45 that are patches, setup hooks, wrapper scripts and
   `python3-env` builders (absolute_gir_path.patch, pkg-config-role-hook,
   pythoncheck.sh, ...). They take seconds. The document's 89 was counted
   the same way, so this does not explain the gap on its own.

2. About 50 of the 237 are REBUILDS OF DERIVATIONS THE BASELINE ALREADY
   CONTAINS. Checked with nix-store -q --outputs: for systemd
   (hrg87xdmvmibsh6mwh9i65mhy03i8887, the very same derivation
   config.systemd.package names in both configurations) the `out` output
   is present and `dev`, `man` and `debug` are missing; util-linux has
   `bin`, `lib`, `mount`, `login`, `swap` and `lastlog` present and `out`,
   `dev`, `man`, `debug` missing; linux-pam and openssh likewise keep `out`
   and have lost `dev`/`man`/`doc`. Those outputs were garbage-collected on
   this host after the baseline was built, and sway's stack needs some of
   them (libsystemd headers for the tray, libpam for seatd's login checks,
   util-linux's dev output through libinput's udev rules). Nix cannot
   rebuild one output of a multi-output derivation, so the whole
   derivation -- and everything between it and the toplevel: cryptsetup,
   lvm2, iptables, iproute2, shadow, sudo, kbd, e2fsprogs, dbus, the
   system units -- is rebuilt to identical store paths. These cost
   wall-clock time on this host and add nothing to the closure. The full
   list is under "Rebuilt baseline derivations" below.

3. The genuinely new work is larger than 89 because of what the measured
   stack pulls in on this pin beyond sway/foot/wvkbd themselves, traced
   with `nix why-depends --derivation`:
     - libjxl, openexr, imath, libhwy, gperftools, gtest, dav1d, libwebp,
       libtiff, lerc, giflib: gdk-pixbuf's loader cache, reached through
       swaybg, which sway-unwrapped hard-depends on for `output bg`.
     - a CROSS-COMPILED python3 with fonttools, pyudev, libevdev, mako,
       markdown, pyyaml: gobject-introspection for glib, reached through
       wvkbd -> pango/cairo -> glib. glib's introspection data is built
       with the target's python under mesonEmulatorHook.
     - go: libcap's Go bindings (libcap -> system-path).
     - libice, libsm, libxcb-{errors,image,render-util,util,wm}, libxft:
       wlroots' X11 *backend* and sway's libxcb-wm, still built with
       Xwayland off.
     - the probes: cage x2, drm_info (pciutils, libdisplay-info),
       libinput's tools, wayland-utils, wlfps, dejavu fonts.
   None of these was in the document's dry run because that run was made
   against a store that still had the GC'd outputs and, judging by the
   count, before this pin's gobject-introspection required a target
   python.

Task 2.4 — derivations that refused to cross-compile
-----------------------------------------------------
One, and it was not in the shell stack itself.

  execline-riscv64-unknown-linux-gnu-2.9.9.2
    ./configure: line 270: pkg-config: command not found
    ./configure: fatal: pkg-config --atleast-version=2.15.1.0 --print-errors -- libskarnet failed

  Reached through: services.seatd (nixos/modules/services/desktops/seatd.nix)
  -> ExecStart wraps seatd in `s6-notify-socket-from-fd` -> pkgs.s6 ->
  execline. execline's configure shells out to pkg-config to find skalibs
  and nixpkgs' derivation for it puts no pkg-config in nativeBuildInputs,
  so the cross build dies in configurePhase before compiling anything.

  What was done: nix/shell.nix no longer uses services.seatd. It declares
  its own seatd unit (Type=simple, no notify wrapper, no s6) and the
  compositor's unit waits for /run/seatd.sock in an ExecStartPre loop
  instead of on a readiness notification. seatd itself cross-compiled
  without complaint. Cost: -3 derivations (s6, execline, skalibs) and one
  fewer supervisor in the closure.

Two failures in this repository's own additions, for completeness, both
fixed in the same commit and neither a nixpkgs refusal:
  - wlfps: `pkg-config` in a cross buildPhase resolves to the build
    platform's, which has no riscv64 wayland-client. It must be
    $PKG_CONFIG, the cross wrapper.
  - cage-rgb565: the probe patch included <drm_fourcc.h>, which is in
    libdrm's include path and cage does not depend on libdrm. The fourcc
    is now spelled out in the patch.
