  nix/patches/uboot-k230/0001-k230_canmv_v3-enable-usbotg0-as-a-peripheral.patch:
    /* The data USB-C, J3, is wired to usbotg0 (schematic: USB0_P/USB0_N to J3
     * A6/A7/B6/B7, with USB0_ID and USB0_VBUS). k230.dtsi leaves usbotg0
     * disabled unless CONFIG_CMD_DFU is set; say so explicitly instead, and as
     * a peripheral, so U-Boot's `ums` can present the TF card to a host there.
     * Other Canaan boards (mrt, lckfb, gt6700) carry the same override.
     */
    &usbotg0 {
    	status = "okay";
    	dr_mode = "peripheral";
    };
    
  Sources unchanged: the same u-boot-2022.10 tarball and the same SDK commit as before.

Three build attempts, two of which the plan did not foresee
-----------------------------------------------------------
1. Fragment appended, nothing else. Turning USB_GADGET on makes symbols visible that the
   defconfig never answered, and a non-interactive make dies in syncconfig:
     Enable USB fastboot gadget (USB_FUNCTION_FASTBOOT) [N/y/?] (NEW)
     Error in reading or end of file.
   Fix: nix/uboot-k230.nix runs 'make olddefconfig' after the append (postConfigure).
2. Configured, then Canaan's own addition to drivers/usb/gadget/dwc2_udc_otg.c -- code the
   old configuration never compiled -- fails under GCC 15.3.0:
     drivers/usb/gadget/dwc2_udc_otg.c:1117:72: error: passing argument 1 of 'readl' makes pointer from integer without a cast [-Wint-conversion]
     drivers/usb/gadget/dwc2_udc_otg.c:1119:68: error: passing argument 2 of 'writel' makes pointer from integer without a cast [-Wint-conversion]
   The lines (overlay, dwc2_udc_otg_probe, marked '// kendryte'):
         #define USB0_TEST_CTL3 (0x9158507cU)
         #define USB1_TEST_CTL3 (0x9158509cU)
         #define USB_DMPULLDOWN0 	(1<<8)
         #define USB_DPPULLDOWN0 	(1<<9)
         u32 usb_test_ctl3 = readl((usbotg_reg == 0x91500000)?USB0_TEST_CTL3:USB1_TEST_CTL3);
         usb_test_ctl3 &= ~(USB_DMPULLDOWN0 | USB_DPPULLDOWN0);
         writel(usb_test_ctl3, (usbotg_reg == 0x91500000)?USB0_TEST_CTL3:USB1_TEST_CTL3);
   GCC 13 warned about this; GCC 14 made -Wint-conversion an error. A u32 register address
   converted to a pointer is well defined on rv64, and the SPL and U-Boot the board booted were
   compiled by GCC 15, so the fix is the narrowest one: KCFLAGS=-Wno-error=int-conversion
   (extraMakeFlags), not a GCC 13 pin for the whole tree and not a patch to the vendor driver.
