# HDMI plug: CMA for scanout buffers (tasks 1.1 and 2.1)

## 1.1 Host build

The board boot files were built with
`nix build "git+file://…?rev=84b8b993#kernelMainlineDrmShellLandscapeHdmiBootFiles"`
(exit 0). `84b8b993` is the integration branch `integ-cma-popup`, which
contains this change's `dcbbab82` (rebased as this branch's source commit),
the keyboard-popup fix and the vision redesign.

The built kernel `/nix/store/b7jgc85iri7i1i77dvr1353yg9whg45m-linux-riscv64-unknown-linux-gnu-7.3.0-rc5`
has these lines in its `config`:

```
CONFIG_CMA=y
CONFIG_DMA_CMA=y
CONFIG_CMA_SIZE_MBYTES=64
```

The running compositor's config,
`/nix/store/gfg4gwkbdslab8x0rkwqsvq5pzfnjw1i-k230-sway.conf`, line 36:

```
output HDMI-A-1 mode 1280x800 transform normal bg #000000 solid_color max_render_time 8
```

## 2.1 Board boot

Evidence class: board shell over SSH after a soft `systemctl reboot` into
`/nix/store/6mmvyyasczi0xsgw9hx2bhx6vrlycr07-nixos-system-nixos-26.11.20260919.20b1ddd`
(installed with `/boot` kernel, initrd and DTB from the same bundle). HDMI was
unplugged and the panel was the active output.

```
$ uptime
 15:41:22  up   0:01,  1 user,  load average: 6.01, 1.76, 0.61
$ dmesg | grep -i cma
[    0.000000] cma: Reserved 64 MiB at 0x000000003a000000
[    0.018038] Memory: 845372K/1048576K available (16490K kernel code, 5952K rwdata, 14336K rodata, 3029K init, 843K bss, 128688K reserved, 65536K cma-reserved)
$ grep -i cma /proc/meminfo
CmaTotal:          65536 kB
CmaFree:           63016 kB
```

At about one minute of uptime, 2.5 MiB of the pool was already in use, which
matches the panel's scanout buffers. The panel's buffers now come from CMA
rather than the buddy allocator.
