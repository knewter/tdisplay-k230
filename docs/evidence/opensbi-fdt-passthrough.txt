OpenSBI fw_jump: fw_next_arg1 before and after leaving FW_JUMP_FDT_ADDR undefined (task 4.2b)
===========================================================================================
2026-09-22, solomon. Why: docs/evidence/opensbi-fdt-lands-in-kernel-image.md -- the vendor
build's FW_JUMP_FDT_ADDR = FW_TEXT_START + 0x2200000 makes fw_jump copy the device tree
32 MiB into the kernel Image, into .BTF. Every command and hash below is pasted from a run.

The make mechanism, checked on GNU Make 4.4.1 with a two-line Makefile before relying on it
-------------------------------------------------------------------------------------------
  J=$(shell printf 0x%X 0x2200000)   # stands for FW_JUMP_FDT_ADDR
  P=$(J)                             # stands for FW_PAYLOAD_FDT_ADDR, recursively expanded
  $ make          ifdef J: TRUE  (value [0x2200000])   ifdef P: TRUE  (value [0x2200000])
  $ make J=       ifdef J: FALSE (value [])            ifdef P: TRUE  (value [])
  $ make J= P=    ifdef J: FALSE (value [])            ifdef P: FALSE (value [])

  So: a command-line assignment overrides the makefile's, and ifdef is false for an
  empty value -- FW_JUMP_FDT_ADDR= on the command line makes firmware/objects.mk:44
  skip the -D and fw_jump.S takes its #else branch. But ifdef looks at a recursively
  expanded variable's UNEXPANDED text, so FW_PAYLOAD_FDT_ADDR=$(FW_JUMP_FDT_ADDR) stays
  'defined' while expanding to nothing, and fw_payload.S:48 becomes 'li a0,':

  First build attempt, makeFlags FW_JUMP_FDT_ADDR= alone:
    /build/source/firmware/fw_payload.S:48: Error: illegal operands `li a0,'
  The card never carries fw_payload (blinux loads fw_jump), so nix/opensbi-k230.nix passes
  FW_PAYLOAD=n rather than a second empty assignment. Second attempt, build flags from the log:
    PLATFORM=generic FW_TEXT_START=0 CROSS_COMPILE=riscv64-unknown-linux-gnu- FW_JUMP_FDT_ADDR= FW_PAYLOAD=n
