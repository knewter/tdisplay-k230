Two fixes this needed
---------------------
1. The kernel emitted no k230-canmv-v3.dtb. arch/riscv/boot/dts/canaan/
   Makefile does not list it, even though the .dts is in the tree; Canaan
   names DTBs explicitly in buildroot instead. Patched into the source via
   applyPatches -- buildLinux ignores a plain postPatch, which cost one
   confused round trip when the derivation hash did not move.

2. The initrd build failed on `modprobe: FATAL: Module ata_piix not found`.
   NixOS's default initrd module list is PC hardware, and with
   autoModules = false the kernel does not build any of it. Cleared the
   defaults: k230_defconfig builds MMC, SDHCI and ext4 in, so the initrd
   needs no modules to find the root filesystem.

NOT YET PROVEN
--------------
That this boots. Everything above is the image being structurally correct,
which is a different claim. The console UART is the known open risk: the
SDK's environment says console=ttyS1,115200 while our kernel command line
says ttyS0, and a console on the wrong UART is indistinguishable from a
board that did not boot.
