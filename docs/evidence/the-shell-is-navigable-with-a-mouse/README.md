# Pointer navigation UX audit

The installed board reproduced the reported navigation gap: a standard mouse click on the overview's “Swipe up for Home” footer left `mode=1 home_selected=0`. [Before capture](before-overview.jpg) is a visually reviewed native capture of that physical board, driven through Sway's standard cursor/button path. It contains only an empty terminal prompt and the shell wallpaper.

[Host tests and before observation](host-and-before.json) record the exact source hashes, installed system, commands and limitations. The host library and policy checks pass. [Final host and headless results](host-final.json) record the rebuilt compositor passing Home, card wheel/activation, bottom mouse drag, tap and cancellation checks. Full system cross-build, installed-board after matrix and physical glass acceptance remain separate gates until recorded below.

The intended routes are:

| Start | Pointer/touch action | Destination |
| --- | --- | --- |
| App | Primary-button drag up from bottom display edge; touch swipe up; four-finger inward pinch in HDMI trackpad mode | Overview |
| Overview | Click/tap the Home footer; swipe/drag up from it | Home, retaining all app windows |
| Overview | Click/tap a live card; four-finger outward pinch in HDMI trackpad mode | Selected live app |
| Overview | Mouse wheel or two-finger scroll | Adjacent card |
| Home | Swipe/primary drag up from bottom display edge | App drawer |
| Drawer | Click/tap app tile | App |
| Drawer | Click/tap top handle; drag it down | Dismiss drawer |
| Any ordinary surface | Primary drag/touch down from top display edge | Notification shade |
| Shade | Click/tap Settings; drag up to dismiss | Settings or previous surface |
| Settings | Click/tap Wi-Fi or Themes, then their Back header | Subpage and back |
| Settings | Click/tap Done | Dismiss Settings |
| Scrollable shell content | Mouse wheel or two-finger scroll | Bounded content movement |

Mouse edge drags are relative pointer actions from the active display's edge. The inactive built-in glass stays a trackpad in HDMI mode; its physical edges are not absolute display coordinates. Four-finger gesture bindings are device scoped. A normal application's two-finger zoom is left available.

All media and raw logs generated by `tests/shell_pointer_navigation.py --capture` initially remain private under its mode-0700 output directory. Home can contain location information and Wi-Fi contains network names; those full captures must not be published. No Wi-Fi connection, theme activation or power action is part of this navigation audit. Native capture, injected events and physical finger observations are distinct evidence classes.
