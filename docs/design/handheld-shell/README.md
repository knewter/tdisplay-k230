# Proposed handheld shell study

The [contact sheet](surfaces.svg), [motion storyboard](motion-storyboard.svg), [transition map](transitions.md), and [Palm motion research](motion-research.md) are original code-native planning artifacts. Each frame is drawn at half of the board's current 568×1232 portrait output; 1 logical pixel maps to 1 panel pixel at the current scale. A 28-pixel button in the sheet represents a 56-pixel panel target. The illustrated top rail is 40 sheet pixels (80 panel pixels), a proposed increase from the installed 56-pixel rail, subject to real-glass reach and content-height review. The mockups show direct drag, swipe and hold cues; any labelled button is a secondary accessible or recovery route. These frames do not depict installed software, measured scanout, confirmed brightness control, vibration, or physical notification behavior. The card image is schematic; live surface continuity must come from the separate card implementation and board proof. The editor/keyboard frame is an app focus example; launcher search is deferred.

The interaction inspiration is **Palm/HP phone webOS**, specifically card continuity, drag/flick scrolling, hold cues, a quick app route, and deferred notification handling. [Palm Pre User Guide, English PDF](https://support.bell.ca/_web/guides/User-Guides/Mobile/PalmOne/Palm-EN/palm_pre_userguide_en%28en%29.pdf) describes these actions on pages 19–20, 23–26, and 32–33. The archived [HP webOS Developer Center dashboard and notification guide](https://www.banneret.nl/webos/documentation/all/dev-guide/mojo/dashboards-notifications.html) describes transient banners followed by deferred dashboard panels. The HP page is a third-party archive of historical developer documentation, not a live vendor endpoint. Both were reviewed as design references on 2026-09-23; neither gives measured timing or evidence that this board implements those behaviors. No Palm images, marks, or assets are copied. LG television webOS design is not used.

Current board grounding: [shell spec](../../../openspec/specs/runtime/shell/spec.md), [portrait image evidence](../../evidence/shell-portrait-image.md), [real-touch keyboard evidence](../../evidence/shell-real-touch-keyboard/README.md), the [handheld UX contract](../../research/handheld-ux/interaction-contract.md), and the selected [card composition architecture](../../research/card-composition-architecture.md). Actual physical contrast, edge reach, notification interruption, and coordinated motion remain **UNVERIFIED**. The board has no established battery capability in these sources; the design does not include battery UI.

Implementation states beyond the five frames use the same geometry: loading shows a labeled progress region and Back; empty shows one clear next action; error preserves the last confirmed state and Retry/Back; critical notification occupies the same preview region with warning color, condition text, Acknowledge and Home targets each at least 56 panel pixels tall. A lower keyboard never covers these routes. Source-color contrast is a design calculation gate; a real-glass camera and finger session is a separate gate.
